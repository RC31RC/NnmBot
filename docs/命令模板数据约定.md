# 命令模板数据约定

## 数据边界

命令返回 `CommandResult(status, replies, actionContext)`。每次调用可有不同的逻辑消息数和内容块，不使用固定 text/data/attachments 槽位：

| 字段 | 用途 |
| --- | --- |
| `replies[].blocks` | 有序 Text / DataView / Image / Markdown / File；直接图片和文件不自动成为模板占位符。 |
| `DataView(viewKey, data, summary)` | 按稳定 viewKey 查插件能力与模板，保留展示 VO；只有声明的摘要才能选 SUMMARY_ONLY。 |
| `replies[].actions` | 消息级链接或填入命令动作，不存原始平台 JSON。 |
| `actionContext` | 关联导航按白名单读取的有界字符串映射，不是模板自动可查的业务仓储。 |
| `status` | 命令状态，不自动成为模板变量。 |

`CommandResponseDispatcher.displayData()` 将本次 DataView 的 DTO 字段放在模板顶层；
例如 DTO 的 `items` 对应 `${items}`，不是 `${data.items}`。
非对象结果包装成 `items`。Jackson 注解会影响字段是否存在及其名称，
不能只看 Java 方法名猜测变量。模板使用的是命令展示 VO，不是数据库实体、
外部 API 的完整 JSON 或渲染器自动拼出的图片清单。

一条命令可以有多份不同样式的完整 HTML，所有样式读取同一份展示数据；
选样式不改变命令数据契约。模板负责结构、样式、循环和展示条件，业务 Service
负责来源选择、文字内容和图片引用解析。

HTML 图片渲染保持原有 Thymeleaf 语法。Markdown 独立保存为 `markdownContent`，必须同时提供
`plainTextContent`；仅支持 `{{field.path}}` 和 `{{#items}}...{{name}}...{{/items}}` 字段/列表插值。
动态 Markdown 字符会转义，不执行表达式或 Bean 方法。纯文本是显式另一种表示，不用正则删除 Markdown 标记。
同一 viewKey 可以分别关联 HTML-only 和 Markdown-only 模板，各展示器按排序选第一份具备自身内容的模板。
管理端 HTML 编辑及预览继续保留。组合回复和通知的配置边界见 [API说明](API与代码结构说明.md)。

## 图片与占位符

- 数据库只存完整 HTML，其中可以包含占位符和固定的远程 URL，不存图片文件、二进制或 Base64。
- 动态图片使用 DTO 中已解析的 `iconUrl`。同一个 URL 可以既作为图标，也作为背景；
  图标和背景是 HTML 的展示角色，不必为了角色不同重复增加 DTO 字段。
- 需要真正不同的背景来源时，再给对应命令 VO 增加有业务含义的字段，
  由 Service 返回实际值；不能在 YAML 或 Java 全局常量中另藏一份背景清单。
- 外部内容是图片 URL 时，它就是占位符的值，不再做第二次模板表达式求值。
  固定 URL 也可直接写在模板的 `src` 中，但它将随模板固定，不会随命令结果变化。
- `/Lotus/...`、`/EE/...`、内容哈希和文件名是 `imageReference`，不一定能被浏览器请求。
  Warframe 复用 `WarframeImageResolver` 及既有图片索引解析成 URL，HTML 不自行猜路径。
- 本次不增加通用渲染资产缓存；既有 Warframe 图片索引缓存保持原有职责。
- 模板仍受现有表达式和脚本限制。只有可信管理员维护模板；远程图片只能使用可信来源，
  URL 可达性不是模板引擎自动保证的。

为了防止多条结果的图片错位，图片和文字必须在同一个条目作用域内绑定：

```html
<article th:each="item : ${items}">
  <img class="background" th:if="${item['iconUrl']}"
       th:src="${item['iconUrl']}" alt="" />
  <img class="icon" th:if="${item['iconUrl']}"
       th:src="${item['iconUrl']}" alt="" />
  <h2 th:text="${item['name']}"></h2>
  <p th:text="${item['description']}"></p>
  <section th:each="ability : ${item['abilities']}">
    <img th:if="${ability['iconUrl']}" th:src="${ability['iconUrl']}" alt="" />
    <h3 th:text="${ability['name']}"></h3>
  </section>
</article>
```

变量名与返回字段一一对应，不能另外建立平行的 `icons[index]`、`names[index]`
数组后靠位置拼接。`${item['iconUrl']}` 的 Map 下标形式适合可选字段：
例如遗物 DTO 使用 `NON_EMPTY`，缺图时字段可能完全不在 JSON 中。
缺图时省略图片节点，布局保留文字；不显示其他物品的图片作为伪造回退。

## 当前展示契约

以下覆盖当前三套可选图片模板。其他命令应以各自插件返回的 DTO 为准，
不能把某个命令的图片字段视为所有命令共有。

### 装备与技能

DTO：`WarframeEquipmentVO`，例如战甲命令；对应可选模板
`wf-warframes-luxe-v1`。

| 层级 | JSON 字段 |
| --- | --- |
| 顶层 | `query`, `category`, `items`, `page`, `totalPages`, `totalCount` |
| `items[]` | `uniqueName`, `name`, `description`, `imageReference`, `iconUrl`, `sourceCode`, `resolutionMode`, `metrics`, `abilities` |
| `items[].metrics[]` | `label`, `value` |
| `items[].abilities[]` | `order`, `uniqueName`, `name`, `description`, `energy`, `imageReference`, `iconUrl`, `sourceCode` |

每页最多 6 个装备条目；装备和每个技能有各自的图片字段，可能为空。
装备背景读取当前 `item['iconUrl']`，技能图标读取当前
`ability['iconUrl']`，不能拿第一页的第一件装备给所有条目填图。
`pagination()` 没有声明 JSON 属性，模板使用 `page/totalPages/totalCount`，
不把该方法当成自动存在的 `${pagination}`。

### 遗物与奖励

DTO：`WarframeRelicVO`，遗物模板为 `wf-relics-luxe-v1`；
奖励查询使用同一 DTO 的 `rewards` 分支。

| 层级 | JSON 字段 |
| --- | --- |
| 顶层 | `query`, `items`, `rewards`, `pagination`, `notice` |
| `items[]` | `relicName`, `vaulted`, `rewards`, `drops`, `quality`, `detailPagination`, `imageReference`, `iconUrl`, `sourceCode`, `resolutionMode` |
| 奖励条目 | `rewardName`, `rarity`, `chance`, `relicName` |
| `items[].drops[]` | `location`, `rarity`, `chance` |

遗物条目有自己的 `iconUrl`，可同时作为主图与背景。当前奖励条目没有图片字段，
不能凭 `rewardName` 假定有奖励图标。遗物及其奖励、地点会按行数和文本量分页，
页内数据可能只有部分明细；顶层的 `rewards` 是奖励查询结果，不是遗物主图列表。
`vaulted=false`、`chance=0` 是有效值，不可按缺失处理。

### 紫卡周成交

DTO：`WarframeRivenWeeklyDisplay`；对应可选模板 `wf-riven-weekly-luxe-v1`。

| 层级 | JSON 字段 |
| --- | --- |
| 顶层 | `query`, `platform`, `pagination`, `sourceCode`, `fetchedAt`, `fetchedAtLabel`, `stale`, `items`, `notice` |
| `items[]` | `weaponName`, `compatibility`, `itemType`, `rerolled`, `avg`, `median`, `min`, `max`, `stddev`, `pop` |

该 DTO 当前没有图标或背景 URL，模板保留无图排版，不再套用固定战甲背景。
若以后要展示武器图标，应在业务层通过武器身份关联与既有图片解析器提供真实字段，
不能根据展示名称拼接远程 URL。`fetchedAtLabel` 是显式 JSON 属性，可直接绑定；
`pop` 是相对交易热度，不是成交样本数。

## 验证与已存模板

`ThymeleafTemplateRendererTest` 检查数据绑定和缺图节点；
`WarframeLuxeTemplateTest` 检查多装备/技能图标归属、遗物背景、缺字段及两份 SQL 的模板一致性。
加 `-Dnnm.template.browser-check=true` 可执行 Playwright 的图片加载、
非空像素和 360/540/840px 长文本布局检查。

仓库中的空库基线与旧库升级脚本已同步模板，但不会自动修改运行中的数据库。
已有模板通过管理端逐项替换完整 HTML，先检查自定义内容。
不要为了更新模板执行 `init.sql`，也不要假定升级脚本的 `ON CONFLICT DO NOTHING`
会覆盖旧模板。


# 关联命令、消息级动作与 QQ Markdown


### 关联组与权限

关联关系由独立命令组表达，管理接口为 `/api/admin/v1/bot-command-groups`，权限使用 `bot:command-group:view`、`bot:command-group:update`。组有名称、稳定编码、启用、版本，成员有稳定命令码、标题和排序；同一命令至多属于一个组。保存、删除均校验组版本，避免静默覆盖其他管理员修改。

`BotCommandGroupServiceImpl` 接收已注册、启用且声明 `allowRelatedAction` 的命令。EXACT 不附参数；PREFIX 必须声明参数契约并完整绑定来源键。`DatabaseCommandRelatedActionProvider` 过滤当前命令、无效目标、身份/群绑定不可用及缺少上下文的目标，按配置限制数量。触发文本取当前命令注册表，不复制过期触发词。

动作属于通用回复模型：`CommandResult` → 有序回复/内容块 → 消息级 `ReplyAction`。`PREFER_NATIVE` 在明确配置 QQ 账号/会话资格且 Markdown 组合合法时生成消息级 keyboard，命令动作 `enter=false`。其他情况使用命令文字或省略可选增强，正文不因此丢失；默认 `nnm.reply.qq.keyboard-accounts: {}` 不宣称拥有原生资格。

动作生成不调用目标插件。用户填入/复制并确认发送后，文本作为普通输入，重新经过命令匹配、逻辑身份、权限、能力角色、冷却和积分。组关系不授予权限，也不继承上次调用者权限。

`POST /api/admin/v1/bot-command-groups/{id}/preview` 按组版本、来源命令、平台/会话、机器人/发送者身份及白名单上下文给出命令与隐藏原因，运行时复用生成及过滤逻辑。预览不是执行许可，实际输入仍完整鉴权。

### 展示策略与发送边界

`PresentationPolicy` 表达默认 `viewOrder`、`composition`、`interaction` 及平台/会话 overrides。HTML 图片继续保留，Markdown 另有模板和显式纯文本；每次按实际结果规划，不把同一命令视为固定数量/类型的回复。

`CommandReplyRouter` 在结果形成后选择唯一可行实例；`ReplyPlanner`/`CommandResponseDispatcher` 准备消息再按顺序发送。不会固定先发摘要再发正文，也不会因为可选导航失败就重做业务或在另一个实例重发完整结果。

默认导航仅为“填入命令、用户确认发送”。当前不支持回调立即执行、短期权限继承或系统身份代执行。

### 参数边界

带参导航遵循以下边界，当前提供上下文的示例为 Wiki 和市场命令；市场目标使用 slug 防止名称尾部数字被当作页码：

- 插件显式提供 `actionContext`，只含声明允许公开的实体及参数；不反射遍历任意 data，不复制整段用户原文。
- 目标声明接受的字段、必需性、长度、格式化和解析边界。PREFIX 使用目标语法生成文本；EXACT 不附参数。
- 缺上下文、实体歧义、列表多实体、参数超长或类型不符时隐藏动作并提供预览原因；只有目标声明无参入口时才退成裸命令。
- 链接动作校验 URL；命令动作处理分隔符、引号和特殊字符，禁止自由表达式和任意脚本。
- 关联导航与“下一页”等业务动作分开拥有，合并、去重和限额时优先保留必要业务操作；导航读取或格式化异常只降级增强。
- 增加组级/来源命令级预览，展示最终命令、QQ/OneBot 表现、隐藏原因及版本冲突；预览不执行插件或真实发送。

若未来改为回调或立即执行，需要独立定义来源校验、短期上下文、防重放及原子消费，不能把当前填入命令协议直接升级为后台执行。

### 验证范围

本地测试覆盖参数契约、白名单、缺参/注入、身份过滤、语义去重、原生/文字计划和 keyboard JSON；浏览器测试核对版本、身份和上下文提交，不代表账号已获平台资格。真实 QQ 账号、群/C2C/频道差异、媒体有效期、主动/被动资格和回复预算仍需逐项验证。

验收至少包括当前命令排除、停用/删除/改触发词、版本冲突、排序、无权限重新输入、可选动作降级、业务正文不丢；带参实现增加歧义、注入、超长、多实体与 EXACT 误附参数测试。源码和前端 API 一起更新，不保留旧 outputMode 构造器或接口别名。
