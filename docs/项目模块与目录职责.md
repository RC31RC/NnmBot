# NnmBot 项目模块与目录职责

> 本文描述后端仓库 `NnmBot` 当前结构（2026-07-29）。管理前端位于独立仓库
> `nnm-admin-web`，不属于本文目录树。

## 1. 根目录

| 路径 | 职责 |
| --- | --- |
| `pom.xml` | Maven reactor 根 POM；声明 Java 21、依赖版本与七个后端模块。 |
| `mvnw` / `mvnw.cmd` / `.mvn/` | Maven Wrapper 与其配置。日常验证使用 `sh mvnw -pl nnm-app -am test`。 |
| `README.md` | 项目简介、模块总览和本地启动提示。 |
| `AGENTS.md` | 项目开发约定；修改前必须遵守。 |
| `scripts/run-dev.sh` | 本地开发启动脚本，不产生生产包。 |
| `docs/` | 架构、数据源、部署、管理端和演进说明。 |
| `nnm-common/` | 无业务域依赖的通用能力。 |
| `nnm-core/` | OneBot 与 QQ 官方消息接入、平台路由、命令插件和执行器。 |
| `nnm-render/` | HTML 模板到图片的渲染能力与渲染 SPI。 |
| `nnm-warframe/` | Warframe 领域、外部 API 适配、缓存和世界状态处理。 |
| `nnm-scheduler/` | 轮询与后续调度任务。 |
| `nnm-admin/` | `/api/admin/v1` 管理 API、Sa-Token 与 RBAC。 |
| `nnm-app/` | Spring Boot 启动、环境配置和 Flyway 迁移。 |
| `.agents/`、`.claude/`、`claude/`、`.idea/` | 本地 AI/IDE 辅助配置，不承载运行时业务。 |

模块依赖方向应保持为：

```text
nnm-app -> nnm-admin / nnm-scheduler / nnm-warframe / nnm-core / nnm-render
nnm-admin -> nnm-core、nnm-warframe（仅应用服务边界）
nnm-scheduler -> nnm-warframe
nnm-warframe -> nnm-core、nnm-render、nnm-common
nnm-core / nnm-render -> nnm-common
nnm-common -> 无业务模块
```

## 2. `nnm-common`：稳定通用层

`src/main/java/com/nnm/bot/common/` 不得反向依赖任何业务模块。

| 目录 | 文件 | 职责 |
| --- | --- | --- |
| `error/` | `ErrorCode`、`CommonErrorCode` | 稳定错误码契约及通用错误码。 |
| `exception/` | `BusinessException`、`SystemException`、`DataNotFoundException` | 业务、系统、数据不存在异常模型。 |
| `exception/` | `GlobalExceptionHandler` | 将异常转换为统一 HTTP 响应。 |
| `http/` | `HttpClient` | 统一 HTTP 调用、类型化 JSON、重试和状态结果模型；约定见 `docs/统一HTTP客户端约定.md`。 |
| `http/` | `HttpClientProperties`、`RestClientConfig` | HTTP 超时、重试、TLS 等集中配置和 `RestClient` 创建。 |
| `response/` | `ApiResponse`、`PageResult` | API 与跨模块分页响应模型。 |
| `retry/` | `RetryBackoff` | 可测试的退避计算。 |
| `validation/` | `BusinessAssert` | 以稳定 `ErrorCode` 表达业务前置条件。 |
| `src/test/java/...` | 同名包测试 | 验证异常映射、HTTP 配置、响应模型、重试和断言语义。 |

| `event/` | `BotMessageEvent` | 标准化的机器人消息应用事件。 |
| `message/` | `BotMessageContext` | 消息、会话和发送所需的显式上下文。 |

| `qqofficial/` | Token、HTTP API、Gateway、消息工厂与发送器 | 接收并适配 QQ 官方机器人事件。 |
| `plugin/` | `BotPlugin` | NnmBot 的**内部命令 SPI**：匹配、处理、稳定命令、说明和顺序。 |
| `plugin/` | `PluginDispatcher` | 以 `order + 规范化 command` 稳定排序；校验全局命令唯一；隔离 `match()` 异常；匹配后的 `handle()` 失败不重复分发。 |
| `plugin/builtin/` | `HelpPlugin`、`StatusPlugin` | 内置帮助与状态命令。 |

`BotPlugin` 当前通过 Spring Bean 收集，适合需要构造注入的业务命令。它不加载任意外部命令 JAR：外部命令若需要数据库、权限或发送器，应先设计明确的受控扩展边界，而不是绕过 Spring 生命周期。

### 4.2 外部渲染 JAR 约定

这是借鉴 Nyx 图片插件思路后的 NnmBot 自有实现，**不依赖 Nyx 或其 `draw-image-plugin`**：

1. 外部 JAR 实现 `com.nnm.bot.render.spi.RenderEngineProvider`；
2. 在 JAR 中放置：

   ```text
   META-INF/services/com.nnm.bot.render.spi.RenderEngineProvider
   ```

   文件内容为实现类的完整类名；
3. 将可信 JAR 放在 `render.plugins.directory`（默认 `./plugin`）；
4. 显式设置 `render.plugins.external-enabled=true` 才会加载；再用
   `render.plugins.provider=<provider-id>` 选择该实现。

外部 JAR 在应用进程内执行代码，不能把用户上传或来源不明的 JAR 放进该目录。默认关闭外部加载，内置 `openhtmltopdf` 始终是稳定回退。
`AUTO` 按 `order + provider id` 稳定选择；内置 Playwright/OpenHtmlToPdf 的顺序分别为 10/20，内存不足时跳过 Playwright。外部 provider 默认顺序为 100，需要参与自动优先选择时必须显式返回更小的 `order`；生产使用更建议配置固定 provider id。
当前只在应用启动时发现插件，不做 Nyx 式运行时热切换。这样可以避免渲染进行中更换实现、旧类加载器无法回收和插件状态迁移不明确；确有不停机切换需求时，应先增加在途任务排空与插件生命周期协议。

## 5. `nnm-warframe`：Warframe 领域与外部协议适配

### 5.1 分层原则

```text
Warframe API JSON
  -> infrastructure/parser/WorldStateParser
  -> domain/model/WorldState（NnmBot 自有、不可变）
  -> application/WorldStateService + 更新事件
  -> 调度、通知、机器人命令、管理端
```

外部 JSON 和第三方 SDK 类型不得越过 parser 进入领域模型、JPA 实体或 API DTO。

### 5.2 目录与文件

| 目录 | 文件 | 职责 |
| --- | --- | --- |
| `application/` | `WorldStateService` | 保存最后成功的世界状态；执行所有变更检测器；发布更新事件。 |
| `application/` | `WorldStateUpdatedEvent` | 对通知、指标和管理端适配器公开的稳定更新事件，携带旧/新状态和发生变化的 section。 |
| `domain/` | `ChangeDetector` | 世界状态变化检测策略接口。 |
| `domain/` | `MessageBuilder` | 将领域数据转为文字或图片的策略接口。 |
| `domain/model/` | `WorldState` | NnmBot 自有世界状态。覆盖告警、裂隙、入侵、突击、执刑官猎杀、各开放世界周期、虚空商人、仲裁、夜波、每日特惠、新闻、活动目标、集团任务、钢铁之路、活动任务和采集元数据。保留早期精简构造器。 |
| `infrastructure/client/` | `WarframeApiProperties` | 世界状态/市场 URL、语言、平台配置及启动校验。 |
| `infrastructure/client/` | `WarframeClientConfiguration` | 启用外部 API 配置绑定。 |
| `infrastructure/client/` | `WarframeApiClient` | 使用 common `HttpClient` 拉取世界状态和市场订单；路径参数编码并记录受限/失败情况。 |
| `infrastructure/parser/` | `WorldStateParser` | 兼容 warframestat.us 与官方 worldState 风格的字段大小写、别名、时间戳格式；区分官方 `Events/Goals` 与聚合 API `news/events`；验证响应至少含一类已知数据；基于规范化 JSON 生成 SHA-256 摘要，不保留原始 JSON。 |
| `infrastructure/cache/` | `WarframeCacheNames` | 唯一的已知缓存区名称。 |
| `infrastructure/cache/` | `WarframeCacheProperties` | 每个缓存区的容量/过期配置和校验。 |
| `infrastructure/cache/` | `WarframeCacheConfiguration` | cache2k `CacheManager`，拒绝未知缓存和 null 值。 |
| `src/test/java/.../client/` | `WarframeApiClientTest` | API 配置校验及市场请求路径编码。 |
| `src/test/java/.../cache/` | `WarframeCacheConfigurationTest` | cache2k 缓存区和约束。 |
| `src/test/java/.../parser/` | `WorldStateParserTest` | JSON 解析、别名/缺失字段和非法响应校验。 |

### 5.3 `WorldState` 相对 Nyx 依赖模型的设计差异

Nyx 直接使用 `io.github.kingprimes.model.WorldState`，该类型随图片插件依赖发布，且可变对象会被翻译工具原地修改。NnmBot 的 `WorldState`：

- 不依赖 Nyx 包、模型包或其渲染库；
- 使用不可变 record 和不可变列表，读操作不会污染缓存快照；
- 将上游字段适配集中在 `WorldStateParser`；
- 提供 `WorldStateMetadata`（来源、抓取时间、上游时间、陈旧标志、schema 版本和摘要），让调用方可以区分实时与陈旧数据；
- 同时支持单个和多个突击/虚空商人，避免把上游列表强行压缩为一个对象；
- 将新闻与活动目标分开建模，解决官方 `Events` 表示新闻、warframestat.us `events` 表示活动的同名异义问题；
- 兼容 Mongo `$date/$numberLong`、秒/毫秒时间戳、`_id.$oid`、`modifierType`、单对象/数组 section，并已用 Nyx 本地真实 `data/status` 全量烟雾验证；
- 为后续节点翻译、奖励池、订阅通知和管理端状态保留明确的领域字段，而不是携带 `Map<String,Object>` 或 `JsonNode`。

这里的“完整”以机器人实际查询、通知和渲染所需的稳定业务概念为边界，不照搬官方响应中的构建开关、实验参数等内部字段。新增业务能力时应先增加明确的 record 和 parser 映射；不得为了追求字段数量把原始 JSON 或 Nyx 可变模型重新泄露到业务层。

## 9. 当前主数据流与后续落点

```text
OneBot -> OneBotMessageHandler -> PluginDispatcher -> BotPlugin

WorldStatePollingTask -> WorldStateProvider -> WarframeApiClient -> WorldStateParser
                      -> WorldStateService -> WorldStateUpdatedEvent
                      -> 变更检测/订阅通知/管理端读模型（后续实现）

模板数据 -> ThymeleafTemplateRenderer -> ImageService -> RenderEngine
                                               -> 内置引擎或可信外部 SPI JAR
```

仍待按 `docs/Warframe外部数据源、代理与缓存演进任务.md` 继续完成的重点包括：最后成功状态正式接入 cache2k、陈旧窗口策略、节点/奖励翻译、订阅持久化与通知投递、Market single-flight 和管理端数据源健康度。
