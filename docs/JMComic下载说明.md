# JMComic 下载说明

JM 命令优先取得整本下载信息，只有整本文件不可用且分页下载已启用时才回退逐图下载。
两条路径分别由配置开关控制。实现必须控制内存、下载大小和页数，并保证生成 PDF 的页序与漫画自然页序一致。

## 下载流程

1. 创建 JM 客户端；账号和密码同时配置时才登录。
2. 请求整本下载信息。
3. 有有效下载地址时以流方式下载整本文件。
4. PDF 直接校验页数和大小；ZIP 安全解压图片后使用既有 PDF 服务生成文件。
5. 整本地址为空、鉴权失败、网络失败或内容无法处理时，仅在分页开关开启时受限并发下载各章节图片。
6. 分图文件按自然页序排序后生成 PDF；整本与逐图均失败时，逐图异常保留整本失败为 suppressed exception。

并发只用于网络下载，页序由稳定的自然排序控制，不能以并发完成顺序生成 PDF。
整本 ZIP 使用原始条目路径排序；PDF 服务严格按调用方传入顺序写页，不按安全临时文件名二次排序。
整本接口直接返回的 PDF 不会被重排，页序沿用上游 PDF 自身的页面顺序。

## 限制与配置

- 整本文件、ZIP 解压和 PDF 输出都受 `max-download-bytes`、`max-pages`、`max-pdf-bytes` 限制。
- 不得将完整下载响应一次性读入 JVM 堆。
- 账号凭据只能通过环境变量或本地私有配置注入，不能提交到仓库。
- `nnm.jmcomic.enabled` 是 JM 总开关。
- `nnm.jmcomic.whole-file-enabled` 单独控制整本文件接口。
- `nnm.jmcomic.page-download-enabled` 单独控制分页下载及整本失败后的兜底。
- 两种方式都关闭时，任务在创建 JM 客户端和访问上游之前被拒绝。
- 两种方式同时开启时优先整本；分页关闭时，整本不可用会返回失败，不会改走分页。
- 整本响应、漫画页数或最终 PDF 触及资源上限时直接失败，不会通过分页路径规避限制。
- YAML 可通过 `NNM_JMCOMIC_WHOLE_FILE_ENABLED` 和
  `NNM_JMCOMIC_PAGE_DOWNLOAD_ENABLED` 分别覆盖两项开关。
- 整本请求超时由 `whole-file-timeout` 控制。

匿名整本下载接口曾出现“请求成功但下载字段全为空”的情况，因此它不是稳定保证。配置有效账号后会重新尝试；
仍未得到有效整本地址时，受限并发逐图下载是正式降级路径。
