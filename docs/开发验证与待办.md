# 本地开发验证与待办

## 常用入口

```sh
./scripts/run-dev.sh
sh mvnw -pl nnm-app -am test
```

需要确认无旧编译产物时执行 `sh mvnw -pl nnm-app -am clean test`。使用真实官方数据时附加 `-Dnnm.test.dataset-directory=/Users/ren/RcGit/warframe-datasource-nnm/data/latest`；这是可选测试输入，不是运行配置中的部署地址。

```sh
node scripts/database/verify-warframe-sql.cjs --hibernate
node scripts/database/verify-bounty-sql.cjs
node scripts/database/verify-worldstate-command-sql.cjs
node scripts/database/verify-bot-reply-routing.cjs
node --test scripts/database/generate-official-dataset-matrix.test.cjs
node scripts/check-docs.cjs
```

数据库检查创建并清理独立的临时 PostgreSQL cluster，不连接实际开发库。外部环境、浏览器布局、真实数据及 Redis 条件测试需显式启用；报告应区分通过与跳过，不能把未执行项写成已验收。

前端在 `nnm-admin-web` 执行：

```sh
npm exec vue-tsc -- --noEmit
npm run lint -- <changed-files>
```

不运行 `mvn package`、`npm run build`，不提交 Git，不向真实平台发送未授权消息。

## 生成参考目录

```sh
sh mvnw -pl nnm-app -am test -Dnnm.catalog.write=true
node scripts/generate-command-reference.mjs
node scripts/database/generate-official-dataset-matrix.cjs
node scripts/check-docs.cjs
```

命令目录的来源是插件元数据和当前 JPA 模型；官方 JSON 目录的来源是 `official-models.json` 和实际类文件。修改源码后同步生成，避免手写计数漂移。

## 待完成的环境验收与实现限制

- 完整应用的多 JVM 实例归属、Redis 断连恢复、多节点共享资源读取与恢复时间，需要真实 Redis 和多进程联合验证；原语测试不能替代。
- OneBot/QQ 真实账号、成员查询、平台回执和权限边界，需要本地凭据及明确的发送授权。
- 平台接收状态不确定时不换实例重复发送；扩展重试需平台明确“未接收”或幂等能力。
- 任意外链通知下载仍禁用，只使用受控的上传资源 ID。
- 4GB、数据库池 5 与真实 Redis 下的联合负载/资源基线，以及文本、图片、交互、拒绝、不确定回执、积分和资源生命周期矩阵，仍需实测。
- 官方 71 个独立输入 DTO 已覆盖当前合同，但部分详情查询仍使用关系树 JSON；新增业务查询应继续采用对应业务 DTO，不宣称所有查询均已逐文件类型化。
- 登录续期不能复活绝对过期的 Sa-Token；具体行为见 [API说明](API与代码结构说明.md)。

只保留仍有效的限制；后续完成后直接更新该条目，不新增历史任务日志。
