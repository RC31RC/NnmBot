# Warframe 数据来源、刷新状态与实现差距

本文件只保留当前开发需要知道的来源规则、刷新状态和未完成边界。历史讨论、阶段清单和已完成任务不在这里维护。

2026-10-10 的数据查漏补缺方案见[桌面最终方案](/Users/ren/Desktop/Warframe数据导入最终方案.md)。
以下“已完成能力”描述现有代码，不代表扩展方案已落地或数据库已导入。

## 当前规则

- 同功能社区资料进入同一业务模型，通过 `sourceCode` 保留来源候选；刷新时按来源独立拉取、解析和 diff。
- 官方 Public Export 保存在独立官方表，不回写社区记录；WorldState 只作为动态运行时数据。
- 来源优先级由对应业务 Service 维护，不建立全局优先级。Repository 获取多个来源候选，
  Service 可选择完整候选，也可按具体业务约定字段合并；入库不淘汰低优先级来源。
- `recordSource=COMMUNITY` 参与对应远程刷新，`SELF_MAINTAINED` 不参与刷新和 diff。
- 同一来源的完整业务键重复或内容矛盾属于上游数据错误，刷新应失败，不把失败当作空数据。
- 输入别名识别和正式名称翻译是两个阶段，不能用别名表覆盖正式翻译。

## 已完成能力

- 社区刷新按来源独立生成新增、修改、删除候选；不变记录只计数。
- Redis 预览支持操作 ID、分页查看、跨页选择、提交合并、物理删除、过期和回滚重试。
- 预览记录和差异按实际 RDT JSON 字节分片，header 最后发布；管理端按来源/变更类型折叠并全选。
- 刷新、合并和人工写入使用同一数据集锁；自维护记录不会被社区刷新删除。
  外部来源记录不能人工修改或删除，只能采纳刷新/上传预览中的上游变更。
- 预览使用数据库基线校验和幂等回执，来源请求失败不会生成删除候选。
- `dict.zh.json` 和 `dict.en.json` 按完整键解析为 `recordKey + locale + displayName`，中英文候选分别保存。
- 普通翻译只登记 plus 双语字典，按自维护、可用官方本地化、plus 中文、plus 英文解析完整键。
- 奖励池按来源选择完整记录，概率和稀有度独立保存；合法高优先级空池不从低来源补拼。
- 遗物唯一正式来源为 `warframe-relic-data/data/Relics.json`；主表和两类明细共享刷新事务。
- `ExportRewards.json`、`ExportBounties.json`、遗物三类数据、仲裁精华和突击代码簿已接入相应模型或刷新链。
- 仲裁排期登记为 `arbitration_schedule`，可在社区页面查询、刷新、预览和采纳；删除限上游覆盖窗口。
- 仲裁排期为 `refreshable=true`、`manageable=false`、`readOnly=true`：
  允许采纳上游新增、修改和删除，不允许人工新增、上传、修改或删除；配置来源后也参加统一批量刷新。
  没有独立定时任务绕过审核直接写入排期表。
- 官方 Public Export 与社区数据分开保存，官方文件下载、解析、持久化均有阶段日志。
- 管理端异步任务的截止时间会在每次进度更新时续期，避免长时间有进度的官方刷新被误判为超时。

## 刷新问题结论

### 官方刷新 500

根因是后台任务在提交时只设置一次固定截止时间。Public Export 下载和解析可能超过默认任务时限，即使任务持续上报进度，读取任务状态时仍会被标记为 `TIMED_OUT`。

当前实现已改为按活动超时判断：任务进入排队、运行或上报进度时都会刷新截止时间和活动键 TTL。仍需使用真实 Redis 执行长任务验收，确认多实例、节点失联和超过租约等边界。

### 社区 `dict.zh.json` 无效

配置的 URL 已确认可以返回 JSON 字典，解析器支持顶层“语言键 -> 文本”对象，不能通过替换 URL 掩盖问题。当前刷新请求日志包含状态码、响应类型、声明长度、实际字节数、字符数、耗时和异常摘要；解析失败日志包含数据集、来源、脱敏地址和异常上下文，不记录完整响应体。

已补充中英文字典解析回归测试。真实刷新仍需在运行环境中确认是否出现代理截断、重定向、超时或上游响应结构变化。

### 字典预览 Redis 大值写入

错误日志中的一次 `PSETEX` 值为 77,013,272 字节，约 73.4 MiB。整批预览重复保存多个 JSON
字段，放进单个缓存值会放大序列化、缓冲区、网络和 Redis 命令负载；PING 超时或连接关闭
不等同于上游下载失败。不能只依据 Redisson 提示就归因为 Netty 线程不足。

当前记录/差异分开保存，每片按 RDT 实际 JSON 的 UTF-8 字节数限制为 256 KiB，单条超限
在写入前拒绝；header 不含全量数据。写入失败补偿清理全部计划键，并覆盖 RDT 写值后
失效通知失败的场景。真实测试服网络、Redis 负载和多实例稳定性仍需运行环境验证，
不能宣称所有连接超时都已由分片消除。未修改数据库/Redis IP、端口或增加 Netty 线程。

### `Unrecognized Type` 读取错误

RDT 使用 Jackson 3，业务映射器使用 Jackson 2；把后者构造的 `JavaType` 传给 RDT，
会在 `tools.jackson.databind.type.TypeFactory` 抛出 `Unrecognized Type`，不是 JSON
来源缺字段。当前缓存读取用 `Object.class`，目标实例直接返回，Map 逐条转换。
已使用实际 RDT `JsonCodec` 验证 header、记录、差异的往返读取和采纳，并拒绝损坏或缺失分片。

Redis 保证的是完整后发布和失败补偿，不是多键原子提交；采纳的持久原子性由 PostgreSQL
选中变更与幂等回执同事务保证。详细流程见 [数据流向说明](Warframe数据流向与命令取数说明.md)。

## 尚未完成

1. `alias_local.json` 尚未完整接入来源登记、解析、保存和测试；中文别名可能对应多个英文对象，不能直接作为唯一键。
   新方案应补 `wfExtraTerms.json` 等真实业务术语来源；`wfTypeAlias.json` 和社区命令类型映射仍不需要。
   其他新增物品、配方、遗物及攻略来源见桌面任务整理，尚未实施。
2. 真实 Redis 多实例长任务、锁租约续期、失锁和节点故障验收尚未完成。
3. 多来源数据集的管理端上传尚未提供完整的来源选择协议，目前无明确来源的上传会被拒绝。
4. 尚未完成所有来源从空库下载、采纳到命令输出的全链路验收；各命令的多来源集成测试仍需补齐。
5. `CommunityJsonMergeEngine` 及其历史测试仍在仓库中，但普通刷新入口已不再使用旧字段合并语义；兼容的 `manual_*` 数据库列也尚未清理。

## 数据库与验证边界

- 空库初始化入口为 `docs/sql/init.sql`；两份独立修复 SQL 已于 2026-10-10 按要求删除。
  本轮未修改基线，翻译、奖励池字段和废弃社区表仍有对齐缺口，旧验证脚本仍有已删除文件依赖。
  应用使用 Hibernate `ddl-auto: validate`，不会自动迁移；不可把此次删除视为结构已合并完成。
- `docs/sql/` 下的校验脚本只验证隔离 PostgreSQL 数据库，不代表真实应用库或远程来源已经完成验收。
- 前端 SSE 续签、断线恢复和 API 前缀适配已经存在，但仍需要浏览器级回归验证。
- 本地参考项目目录只用于核对来源和业务含义，运行时不依赖这些目录。
