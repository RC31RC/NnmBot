# RDT 与多实例运行

## 目录和使用方式

RDT 是分布式协作基础设施；每节点缓存、解析、渲染和 Spring 本地事件保持各自职责。定时入口统一在所属模块 `schedule`；跨实例消息统一在 `mq` 的四个目录：

| 目录 | 职责 |
| --- | --- |
| `consumer/<业务>` | 消费者实现及声明式消费入口 |
| `message/<业务>` | 消息载荷 |
| `messagedescriptor/<业务>` | 发布描述符、队列身份和投递配置 |
| `consumerdescriptor/<业务>` | 消费策略描述符 |

生产者和注册配置引用以上定义，不再从 `messaging`、`listener` 等位置寻找 MQ 类型。`event` 中的 Spring 应用事件只在当前 JVM 发布，不当作跨实例消息。

调度、消费及方法互斥优先使用 `@RdtScheduled`、声明式消费注解和 `@RdtLock`；ID、发布和跨连接 owner lease 使用编程式 API。描述符、任务身份与容量必须按业务配置，不复制匿名策略。

## 哪些任务在哪执行

- 集群统一认领的工作使用 RDT 调度，例如通知任务执行、共享资源清理等；实际入口见各模块 `schedule`。
- WorldState、仲裁、每节点索引/内存快照等在每个 JVM 运行，使用本地调度。由一个实例刷新不会填充其他节点内存，不能机械替换为 RDT 单次认领。
- 本地连接心跳、重连和每节点状态采集随实例/连接生命周期管理，不当作独立集群业务任务。

## 连接归属和操作

机器人实例使用 owner lease 确保活动连接归属明确。旧 socket 回调不得覆盖新连接状态；租约释放、重连和连接停止按实例生命周期执行。跨节点群组发现、主动通知及命令执行显式携带目标实例和业务身份。

同一逻辑群可绑定多个实例，能力、启用状态和优先级参与选路。对平台已经接收或接收状态不确定的发送，不能擅自换实例重发；只有能证明未接收或有明确幂等能力时才允许安全的重试策略。细节见 [实例与路由](多渠道实例与群组回复路由.md)。

## 锁与事务

本项目把 `@RdtLock` 视为方法级互斥，**不能假设锁自动持续到外层事务最终提交**。事务级锁累积管理器暂未实现。需要跨事务提交维持互斥时，先明确传播、释放和失败边界；数据库一致性优先由短事务、行锁、唯一约束和明确状态转换保证。

通知任务领取/状态更新只在短事务内使用行锁；不跨渲染、平台请求、线程池或异步回调持有 JPA 事务。禁止通过 ThreadLocal 跨 WebSocket、CompletableFuture、调度回调传播事务、锁或会话身份。

## 资源与验证边界

Redis、数据库连接池与执行器预算必须联合评估。默认数据库池上限为 5，部署预算为 4GB；不添加无界执行器。执行资源由 `ExecutorConfig` 与 `nnm.executor.*` 配置，拒绝策略保留背压语义。

本地启动读取配置文件中的 RDT 和 Redis 设置，检查用例按需启用外部环境。RDT 原语测试通过不代表完整应用多 JVM 调度、掉线恢复或真实账号发送已经验收；未完成项统一见 [开发验证与待办](开发验证与待办.md)。
